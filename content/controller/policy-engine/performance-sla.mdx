Path monitors: what to probe, how often, and the latency, jitter, loss and MOS limits that decide whether a path counts as healthy. Performance SLA is one feature with several views — SLA Settings and SLA Thresholds are sub-tabs of it.

Scope is the same across the Policy Engine: a policy with **Apply fleet-wide** set reaches every device, otherwise it is narrowed to an organization. There is deliberately no device picker — configuring a single router is what that router's own CPE page is for.

<Callout type="info">Served by the shared `PolicyEngine` component via the `/policy-engine/:tab` route. Facts below describe that component, which renders several tabs.</Callout>

## What you can do here

### Actions

- **Delete resource** — Removes a policy via `DELETE /api/v1/nsbond/path-monitor/<id>/`.
- **Edit resource** — Creates and edits a policy through the shared resource form. Fields: Probe target, Probe type, Probe interval (ms), Failures before down, Successes before up, Max latency/jitter/loss, Min MOS score, MOS codec, Detect mode, UDP echo port, Withdraw static route when inactive, SLA fail/pass log intervals, Target path, WAN members.

### Reading and lookups

- **Browse and search resource** — Lists policies from `GET /api/v1/nsbond/path-monitor/`, with columns Name, Probe target, Max latency, Max jitter, Max loss, Scope, State.

**Opens:** `ResourceTable` — some actions above are performed in it.
