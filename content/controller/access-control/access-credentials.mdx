How the controller logs in to devices in order to push configuration — the SSH credentials themselves. A credential has a connection type and an organization, and can be set to attach automatically to new devices in that organization rather than being applied by hand.

SSH keypairs are generated here, so a private key never has to be pasted in from elsewhere.

## What you can do here

### Actions

- **Create credential** — Adds one. **Auto add** is the field that matters: with it set, the credential attaches to every new device in that organization, which is what stops a freshly registered device sitting unreachable.
- **Delete credential** — Removes it. Any device whose only connection used it can no longer be reached, so check the device Credentials tabs first.
- **Edit credential** — Changes a credential. Devices already bound to it pick the change up on their next connection attempt.
- **Generate ssh keypair** — Creates a keypair in place, so the private half is never carried in from somewhere else.

### Reading and lookups

- **Browse and search credentials** — The SSH credentials the controller uses to reach devices. A credential is bound to devices through a connection, which is what the device's own Credentials tab manages.
- **Browse and search groups** — The device-group list — the second half of the scope picker, and the group field on this page's forms.
- **Browse and search organizations** — The organization list — what the scope picker narrows the page by, and what fills the Organization field on its forms. Almost every record in the controller is organization-scoped, which is why this call appears on so many pages.

**Opens:** `CredentialFormModal` · `useScopeOrg` — some actions above are performed in these.
