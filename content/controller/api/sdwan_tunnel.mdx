      - content: >-
          "Control Plane" is the operator-facing name for ``config.Vpn`` servers

          (admin at ``/admin/config/vpn/``). The VPN model has no online/offline

          field, so reachability is derived the same way the VPN-uptime report
          does:

          match each VPN ``host`` to a managed Device (by ``management_ip`` /

          ``last_ip``) and treat the server as *online* when that device's
          monitoring

          status is ``ok``. A VPN whose host matches no monitored device — or
          matches

          a device that is not ``ok`` — counts as *offline* (reachability
          unconfirmed).


          Response shape::

              {"total": 3, "online": 2, "offline": 1, "as_of": "2026-06-04T..Z"}

          Aggregate counts only — never VPN names, hosts, or device IDs.
          Org-scoped:

          non-superusers only ever count VPNs in their own organizations.
        heading: aggregate-control-plane-vpn-server-count--reachability-for-thecontrol-plane-card-on-the-dashboard-overview-tab
      - content: >-
          Powers the **Interface Throughput** card (Inbound + Outbound
          doughnuts) on

          the WAN Uplinks dashboard tab.


          Query params (forwarded to
          :func:`get_data_usage_payload_for_request`):
            * ``period`` — ``1d`` (default) | ``3d`` | ``7d`` | ``30d`` | ``365d``
            * ``location_id``, ``floorplan_id``, ``ifname`` — optional filters
            * ``nocache=1`` to bypass the 60s cache (debugging only)

          Response shape::

              {
                "inbound":  [{"bucket": "<100", "count": 12}, ...],   # rx-direction
                "outbound": [{"bucket": "<100", "count": 8},  ...],   # tx-direction
                "total_interfaces": 16,
                "as_of": "2026-05-08T10:30:00Z"
              }

          The four buckets are always present in the same order:

          ``<100 / 100-500 / 500-1000 / >1000`` (Mbps).
        heading: aggregate-inboundoutbound-mbps-distribution-across-all-org-wan-interfaces
      - content: >-
          Aggregate SD-WAN overlay (NsBondTopology) count + status for the

          **SD-WAN Overlays** card on the dashboard Overview tab.


          Each :class:`NsBondTopology` is one overlay fabric. Counts are grouped
          by

          the topology ``status`` state machine into three pills:


          * ``deployed`` — status ``deployed``

          * ``error``    — status ``error`` / ``failed``

          * ``pending``  — everything else (draft / computed / validated /
          deploying /
            undeploying)

          Response shape::

              {"total": 5, "deployed": 3, "pending": 1, "error": 1, "as_of": "..Z"}

          Aggregate counts only. Org-scoped exactly like the nsbond map-tunnels
          view.
        heading: json_list
