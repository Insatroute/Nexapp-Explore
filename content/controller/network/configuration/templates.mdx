Configuration templates — the units of config that get pushed to devices. Each row shows the backend it targets, whether it is tied to a VPN, its tags, and how many devices it is applied on, so a template nobody uses is visible as such.

**Two different things live here, and the tabs keep them apart.** A **template** is authored by you and rendered per device — the controller fills in that device's variables at push time. A **backup template** is a snapshot taken FROM a device, stored as raw config; it is what Devices → *Back up config* writes into, and what Devices → *Apply backup* pushes back out. One is generated for a device, the other was captured from one.

Two flags change how a template attaches: *default* attaches it to new devices automatically, and *required* means it cannot be detached from a device that has it.

## What you can do here

### Actions

- **Delete backup template** — Removes a stored snapshot. Nothing on a device changes — a backup is a record, not an attachment.
- **Delete template** — Removes a template (`DELETE /controller/template/<id>/`). The *Applied on* column is the thing to read first: it says how many devices lose this config.

### Bulk actions

- **Apply or push backup (in bulk)** — Pushes a stored backup's raw UCI to devices over SSH. The same operation as Devices → *Apply backup*, started from the backup instead of from the selection.

### Reading and lookups

- **Browse and search backup templates** — The snapshots taken from devices, listed in the second tab. Devices → *Back up config* is what creates them, and only when the config has actually changed since the last one.
- **Browse and search organizations** — The organization list the scope picker filters by; templates are org-scoped.
- **Browse and search templates** — The authored templates, from `GET /controller/template/` with `kind=manual` — which is what keeps backups out of this tab even though both are templates to the backend.
- **View pushed config** — Shows what was actually pushed for a device, from `/config-compare/pushed/<id>/` — the rendered result rather than the template it came from, which is what you compare against when a device looks wrong.

**Opens:** `BackupTemplateTable` — some actions above are performed in it.
